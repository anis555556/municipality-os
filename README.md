# Municipality OS — بلدية البريج

منصة تشغيل بلدية متعددة الجهات: واجهة عربية RTL، بوابة مواطن، لوحة إدارة، REST API، PostgreSQL/PostGIS، صلاحيات خلفية، وخريطة MapLibre تفاعلية. **كل أسماء المرافق والمشاريع والأرقام والطقس والحسابات في بيانات العرض تجريبية وليست معلومات بلدية رسمية.**

## البنية

- **واجهة الويب:** Next.js 15 App Router، React 19، TypeScript، Tailwind-compatible CSS tokens، Framer Motion، وواجهات متجاوبة من اليمين إلى اليسار.
- **الخريطة:** MapLibre GL JS مع نمط متجهي من OpenFreeMap وبيانات OpenStreetMap، وطبقة مبانٍ ثلاثية الأبعاد عند توافر بيانات الارتفاع. لا يوجد مفتاح Google Maps أو Mapbox.
- **API:** Route Handlers في Next.js، REST/JSON، تحقق Zod، رؤوس أمنية، فحص Origin، وتحديد معدل الطلبات في PostgreSQL المشترك بين نسخ التطبيق.
- **الجلسات والصلاحيات:** كلمة مرور bcrypt، رمز جلسة عشوائي مخزن بصمة HMAC له في قاعدة البيانات داخل Cookie من نوع HttpOnly/SameSite، وانتهاء بعد 14 يومًا. التحقق من الدور والبلدية في الخلفية.
- **البيانات المكانية:** PostgreSQL + امتداد PostGIS. يحتفظ التطبيق بإحداثيات الطول والعرض لتغذية الخريطة مع عمود `geometry(Point,4326)` وفهارس مكانية.
- **المستأجرون:** كل سجل تشغيلي مرتبط بـ`municipalityId`. يختار SUPER_ADMIN البلدية من مبدّل المستأجر؛ المستخدمون الآخرون مربوطون ببلديتهم.

```text
src/app/                الصفحات وREST API
src/components/         الخريطة، بوابة المواطن، لوحة الإدارة، المساعد
src/lib/                Prisma، الجلسات، التحقق، المستأجر، التدقيق
prisma/schema.prisma    نماذج البيانات والعلاقات
prisma/migrations/      SQL المنشور
prisma/seed.ts          بيانات وحسابات العرض التجريبية
```

## الأدوار

| الدور | نطاق الصلاحية |
|---|---|
| `SUPER_ADMIN` | إنشاء البلديات وإدارة المستأجرين وتجاوز نطاق البلدية بإجراء خادمي |
| `ADMIN` | إعدادات البلدية وإدارة المستخدمين والمحتوى والسجلات داخل بلديته |
| `EDITOR` | تحرير الخدمات والمشاريع والمرافق والمحتوى ضمن البلدية |
| `STAFF` | مراجعة الطلبات والشكاوى والمواعيد وتحديث حالات المعالجة |
| `CITIZEN` | خدماته وطلباته وشكاواه ومواعيده وإشعاراته ومشاركته فقط |

لا تعتمد الصلاحيات على إخفاء الروابط؛ كل Route يتحقق من الجلسة والدور والمستأجر قبل التغيير أو القراءة الخاصة.

## المتطلبات والتشغيل المحلي

- Node.js 20.19+ أو Node.js 22+
- PostgreSQL 16 مع PostGIS 3.x، أو Docker Compose المرفق
- pnpm 9+ أو npm

```bash
cp .env.example .env
# غيّر AUTH_SECRET إلى قيمة عشوائية طويلة قبل التشغيل
docker compose up -d database
pnpm install
pnpm db:deploy
pnpm db:seed
pnpm dev
```

افتح `http://localhost:3000`. يعمل `postinstall` تلقائيًا على `prisma generate`. وللتشغيل الكامل باستخدام الحاويات:

```bash
# عيّن AUTH_SECRET قويًا في .env أولًا
docker compose up --build
```

يمكن استخدام npm بدل pnpm بالأوامر المكافئة: `npm install` ثم `npm run db:deploy` و`npm run db:seed` و`npm run dev`.

## الحسابات التجريبية

يُنشئ `pnpm db:seed` مسؤول بلدية ومواطنًا تجريبيين. عيّن `DEMO_ADMIN_PASSWORD` و`DEMO_CITIZEN_PASSWORD` قبل seed لتحديد كلمات المرور بنفسك. إذا تُركت فارغة، يُولّد seed كلمة عشوائية قوية ويطبعها **مرة واحدة** في خرج الطرفية؛ لا يعيد كتابتها عند تشغيل seed لاحقًا. البريدان الافتراضيان `admin@bureij.local` و`citizen@bureij.local` لأغراض العرض المحلية فقط.

يمكن إنشاء مسؤول عام منفصل بتعيين `SUPER_ADMIN_EMAIL` و`SUPER_ADMIN_PASSWORD`. لا يُنشأ SUPER_ADMIN تلقائيًا بكلمة مرور ثابتة.

## متغيرات البيئة

انسخ `.env.example` إلى `.env`، ولا تضع ملف البيئة أو بيانات الاعتماد في Git.

| المتغير | الاستخدام |
|---|---|
| `DATABASE_URL` | عنوان PostgreSQL مع `schema=public` |
| `AUTH_SECRET` | سر عشوائي بطول 32 حرفًا على الأقل لإنتاج بصمة رموز الجلسات |
| `DEFAULT_MUNICIPALITY_SLUG` | البلدية الافتراضية للزيارات الجديدة وseed |
| `NEXT_PUBLIC_APP_URL` | أصل الواجهة المسموح به لطلبات API |
| `DEMO_ADMIN_EMAIL`, `DEMO_ADMIN_PASSWORD` | حساب الإدارة الاختياري الذي ينشئه seed |
| `DEMO_CITIZEN_EMAIL`, `DEMO_CITIZEN_PASSWORD` | حساب المواطن الاختياري الذي ينشئه seed |
| `SUPER_ADMIN_EMAIL`, `SUPER_ADMIN_PASSWORD` | إنشاء SUPER_ADMIN اختياري أثناء seed |

## قاعدة البيانات وPrisma

```bash
pnpm db:generate       # توليد Prisma Client
pnpm db:migrate        # ترحيل تطويري وإنشاء ترحيل جديد عند تعديل المخطط
pnpm db:deploy         # تطبيق الترحيلات المسجلة في بيئة النشر
pnpm db:seed           # إدراج بلدية البريج ومحتوى العرض التجريبي
```

تتضمن النماذج البلديات والمستخدمين والجلسات والخدمات والطلبات وأحداث تتبعها والشكاوى وأحداثها والمشاريع والمرافق والأخبار والفعاليات والإعلانات والاستطلاعات والاقتراحات والإشعارات والمواعيد والموظفين والمرفقات وسجل التدقيق ومخازن تحديد المعدل. توجد فهارس للمستأجر والحالة والتواريخ والإحداثيات.

تتضمن أول migration تفعيل `postgis` وفهارس GIST للمواقع. يدعم Render Postgres امتداد PostGIS على PostgreSQL 13 فما بعد، ويضبط Blueprint هذا المشروع PostgreSQL 16.

| `/api/services`, `/api/projects`, `/api/facilities`, `/api/news`, `/api/events`, `/api/announcements`, `/api/surveys` | قراءة عامة للمحتوى المنشور وخدمات البلدية |
| `/api/requests`, `/api/complaints`, `/api/appointments` | تقديم ومتابعة الطلب والشكوى والموعد |
| `/api/proposals`, `/api/surveys/:id/vote` | المشاركة والتصويت مرة واحدة للحساب |
| `/api/map-data`, `/api/search` | طبقات المواقع والبحث العام |
| `/api/analytics`, `/api/audit-log` | مؤشرات وسجل إدارة محميان |

## الأمان والحدود التشغيلية

- كلمات المرور تُهش بـbcrypt، وصمات رموز الجلسات فقط تُخزن في قاعدة البيانات.
- تحقق Zod يطبق على التسجيل والدخول والطلبات والشكاوى والمواعيد والإعدادات وCRUD المحتوى.
- تحديد المعدل ذري ومشترك على PostgreSQL، مع انتهاء تلقائي للسجلات.
- CORS/Origin مقصور على أصل التطبيق ورؤوس الحماية مفعلة. قيم المحتوى تعرض كنص React، لا كـHTML موثوق.
- رفع الصور يقبل JPEG/PNG/WebP حتى 5MB ويقدمها بمسار يتطلب جلسة وتطابق بلدية.
- لا توجد بوابة دفع إلكتروني أو تكامل مصرفي.
- لا توجد خدمة طقس أو تنبيهات رسمية مربوطة؛ درجة الحرارة والتنبيهات والمشاريع المعروضة بيانات توضيحية.
- خريطة OpenFreeMap تحتاج اتصالًا خارجيًا أثناء تحميل الصفحة. تعتمد جودة ارتفاعات المباني والتغطية على بيانات OSM المتاحة للموقع، ولا تنشئ المنصة مجسمات مبانٍ من صور ثابتة.
- إدارة البريد/إعادة تعيين كلمة المرور ورسائل SMS، التخزين السحابي للمرفقات، وموفر ذكاء اصطناعي خارجي غير مدمجين؛ المساعد الحالي محلي قائم على قواعد معرفة قابلة للاستبدال.

## النشر على Render

1. ارفع مجلد `municipality-os` إلى مستودع GitHub مستقل.
2. اختر **New → Blueprint** وحدد `render.yaml` من جذر المستودع.
3. راجع الخطة والمنطقة وقاعدة PostgreSQL وخدمة Docker قبل إنشاء الموارد. يضيف Render `DATABASE_URL` ويولّد `AUTH_SECRET` للـWeb Service.
4. عيّن `NEXT_PUBLIC_APP_URL` إلى عنوان Render العام. يطبق أمر البدء ترحيلات Prisma ويشغّل seed idempotent؛ كلمات مرور حسابات العرض العشوائية تظهر مرة واحدة في خرج أول seed. أنشئ SUPER_ADMIN منفصلًا بإضافة `SUPER_ADMIN_EMAIL` و`SUPER_ADMIN_PASSWORD` الآمنين لبيئة التنفيذ ثم أعد تشغيل seed أو الخدمة.
5. يفحص Render `/api/health`. عند بدء الخدمة يطبق `prisma migrate deploy` قبل تشغيل خادم Next.js.

يدعم ملف Blueprint `dockerCommand` و`healthCheckPath` وفق مرجع Render. تتطلب قاعدة البيانات المدارة دعم PostGIS لتطبيق migration المكاني؛ إن لم يكن الامتداد متاحًا، فعّل قاعدة PostgreSQL تسمح به قبل النشر. رابط الخريطة الخارجية يعمل من المتصفح ولا يحتاج رمز Mapbox.

## الإتاحة

الواجهة تدعم لوحة المفاتيح، تسميات عناصر النماذج، رسائل الحالة، إعدادات تباين عالٍ وخط أكبر ووضع مبسط، وتحترم `prefers-reduced-motion`. الخريطة التفاعلية مرفقة بعناوين وأزرار تحكم، ويظل كشف الموقع اختياريًا ويتطلب سماح المتصفح.
